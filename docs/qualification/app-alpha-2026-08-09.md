`GLYPHKILN_REAL_POSTGRES_QUALIFICATION=1` and an injected, unrecorded
`GLYPHKILN_REAL_POSTGRES_DATABASE_URL`:

```text
npm run test:postgres-qualification --workspace @glyphkiln/app
```

`real-postgres-qualification.test.ts` completed four tests:

- all seven migrations applied forward, rolled back with explicit data-loss
  permission, applied forward again, and then reapplied idempotently;
- workspace-qualified queue inspection did not disclose a foreign job, and a

  installation limit, leaving one immutable resource row and one blob.

Outcome: **4 tests passed** against PostgreSQL 17.6.

## Findings resolved during qualification

The live drills found and resolved issues not reproduced by the prior emulated
tests:

- production `postgres.js` JSONB parameters were being double encoded;
- concurrent Compose services raced while exporting the same locally built
  image;
- the prior ClamAV image pin was not arm64-compatible;
- ClamAV readiness could pass with a newer on-disk daily database than the one
  loaded by ClamD;
- an app published from only Docker-internal networks was unreachable from the
  host;
- a multi-network app hostname could bind a different interface than the
  reverse proxy resolved.

Regression tests now cover structured PostgreSQL JSON parameters, the
single-owner image build, exact pinned services, signature-matched ClamAV
readiness, the HTTPS proxy topology, and the network-scoped app bind alias.

No renderer, schema, template, typography, procedural algorithm, or intended
output pixel changed, so no renderer or algorithm version was advanced.
